# Issue tracker: GitHub

Repository: jokomugi/seegram-fork. Personal-fork specs and issues live in its GitHub Issues; use gh with an explicit repository argument.

Publish agreed specs and implementation issues in this repository. Apply ready-for-agent to implementation issues and record native blocking relationships. Keep upstream SeeGram reports and the external ai-tdesktop queue separate.

Write multiline issue and PR bodies to a temporary file and pass --body-file. Read the complete issue and comments before working from it. Close implementation issues only after their acceptance criteria pass; report any remaining build or release limitations.

PRs are not an incoming request surface.
